# Review follow-up (CI)

Runs without any user: never ask a question, never wait for a confirmation. When something
needed is missing, stop and say why in the final output, without posting anything.

## 1. The pull request

- `gh pr view <n> --json number,title,author,baseRefName,headRefOid,commits,state`.
  The PR is closed or a draft → stop.
- The owner and the repository come from the argument, or else from
  `gh repo view --json owner,name`.
- Read the code **at the PR head** (`git show <headRefOid>:<path>`); fetch the missing commits
  with `git fetch origin pull/<n>/head`.

## 2. The open findings

Get the review threads:
```
gh api graphql -F owner=<owner> -F repo=<repo> -F n=<n> -f query='
query($owner:String!,$repo:String!,$n:Int!){
  repository(owner:$owner,name:$repo){ pullRequest(number:$n){
    reviewThreads(first:100){ nodes{
      id isResolved isOutdated path line originalLine
      comments(first:50){ nodes{ databaseId author{login} body createdAt originalCommit{oid} } }
    } } } } }'
```

A finding is an **unresolved** thread whose first comment isn't from the PR author nor from an
analysis bot (`sonarqubecloud`, `github-advanced-security`…); the findings of `claude[bot]` count.
No finding → stop without posting anything.

For each finding, note: file, line, summary, the commit it was made on (`originalCommit`), the
replies, and the date of the last comment of `claude[bot]` in the thread, if any.

## 3. What changed

- **Baseline** = the commit given in the last follow-up comment of `claude[bot]` on the PR
  (marker `<!-- review-followup: <sha> -->`, see step 6), or else the `originalCommit` of the
  oldest finding.
- Follow-up diff = `git diff <baseline> <headRefOid>` and `git log --oneline <baseline>..<headRefOid>`.
  Baseline unreachable (rebase) → use the merge-base with the target branch and say so.
- No commit since the baseline → stop without posting anything.

## 4. Assess each finding

Read the current code around the location (it may have moved), the follow-up diff of the file
and the replies of the author, and give one verdict:

- **Fixed** — the defect is gone and the fix is correct: replay the failure scenario of the
  finding against the new code; a change at the right place isn't enough.
- **Partially fixed** — some cases remain or the fix is incomplete.
- **Not addressed** — unchanged and no convincing reply.
- **Disputed – justified** — unchanged, but the author's reply shows the finding was wrong.
- **Disputed – not justified** — unchanged and the reply doesn't hold.
- **Obsolete** — the code was removed or rewritten; check the rewrite doesn't carry the defect.

The project rules (AGENTS.md) require tests with any code change: flag the fixes without tests.

## 5. Review the follow-up commits

Review the follow-up diff only, not the whole PR, for correctness bugs brought by the fixes:
regressions, broken call sites, missing cases, tests that don't test what they claim. Follow
AGENTS.md. Report only issues verified in the code, each with a concrete failure scenario. Don't
report again an issue already raised in an open thread.

## 6. Publish (--comment only)

Without `--comment`, print the report of step 7 and stop. With it, write in the language of the
review comments and end each text with `_Generated by [Claude Code](https://claude.ai/code)_`.
Write each text in a file under `.review-followup/` in the working directory, and pass it to `gh`:

1. **Resolve** the threads of the findings Fixed, Disputed – justified and Obsolete (without a
   defect carried over), with no reply:
   `gh api graphql -f id=<thread id> -f query='mutation($id:ID!){ resolveReviewThread(input:{threadId:$id}){ thread{ isResolved } } }'`
2. **Reply** in the threads of the findings Partially fixed, Not addressed and Disputed – not
   justified, and leave them open: the verdict, what is still wrong (file:line at the PR head,
   concrete scenario) and what is expected. Skip a thread whose last comment is already a reply
   of `claude[bot]` when no follow-up commit touches its file: the answer would be the same.
   `gh api repos/<owner>/<repo>/pulls/<n>/comments/<first comment databaseId>/replies -F body=@<file>`
3. **Post one PR comment**: a summary line (x/y findings fixed, threads still open), the new
   issues of step 5 if any, and as its last line the marker `<!-- review-followup: <headRefOid> -->`
   so that the next run only reviews the newer commits.
   `gh pr comment <n> --body-file <file>`

Never unresolve a thread, approve the PR or request changes.

## 7. Report

Print: the summary line, a table `# | File:line | Finding | Verdict | Comment`, the new issues
(file:line, defect, scenario), and what was posted, if anything.
